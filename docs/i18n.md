# docs/i18n.md

言語・文言キーを追加する手順。両モジュールにまたがる。仕組みと制約（マスターとコピー、`locale_impact.py` によるリリース判定）はルートの [`../AGENTS.md`](../AGENTS.md) の「Shared locale resources」、各モジュールの i18n の構造はそれぞれの `AGENTS.md` を参照。

共通の前提:

- 編集するのは**ルートの `locales/` だけ**。`desktop/frontend/src/locales/` と `chrome-extension/src/locales/` は `python3 scripts/sync_locales.py` が書き出すコピーで、直接編集すると CI（`check-locales.yml`）が落ちる
- ロケールコードは Claude 公式のコード（地域サブタグ付き。例: `en-US` / `ja-JP` / `es-419`）
- **各モジュールのソースは自分が使うキーだけを宣言する**。拡張だけが使うキーを desktop の `RawMessages` に足したり、その逆をしたりしない（`locale_impact.py` の判定が崩れ、共有文言の変更が両方のリリースになる）

## 言語を追加する

1. `locales/<code>.json` を新規作成する。既存の `en-US.json` をコピーして全キーを翻訳するのが安全（キーや `{token}` が `en-US.json` と揃っていないと `sync_locales.py` が落ちる）
2. `python3 scripts/sync_locales.py` で両モジュールへ同期する
3. desktop（`desktop/frontend/src/i18n.ts`）:
   - JSON の `import` を1行足す
   - `SUPPORTED_LOCALES` に `<code>` を足す
   - メッセージ表に `'<code>': build(<変数>)` を1行足す
4. desktop（`desktop/frontend/src/SettingsWindow.tsx`）: Language セレクタに `<option value="<code>">` を足す。表示名はその言語の自称表記（例: `日本語 (日本)` / `español (España)`）
5. 拡張（`chrome-extension/src/i18n.js`）: `TEMPOC_LOCALES` に `<code>` を足す。desktop の `SUPPORTED_LOCALES` と一致させること。拡張には言語セレクタは無い（claude.ai のアカウント言語に従う）

## 文言キーを追加する

1. `locales/` の**全ファイル**に同じキーを足す。パラメータ付きの文言は `{token}` プレースホルダで書き、全ロケールで同じ token を使う
2. `python3 scripts/sync_locales.py` で同期する
3. そのキーを使うモジュール側だけを変更する:
   - **desktop**: `i18n.ts` の `RawMessages` にフィールドを足す（あるロケールで欠けると `tsc` が落ちる）。パラメータ付きなら `Messages` 側の関数シグネチャと `build()` の組み立ても足す
   - **拡張**: `options.html` の要素に `data-i18n="<key>"` を付け、要素内の英語テキストを `en-US.json` と同じ文面にする（JSON の読み込み前に見えるフォールバック）。JS から使うなら `t.<key>`。参照したキーが `en-US.json` に無いと `sync_locales.py` が落ちる
4. `python3 scripts/locale_impact.py` で、どちらのモジュールがリリース対象になるかを確認する
